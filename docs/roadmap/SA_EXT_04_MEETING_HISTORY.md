# SA-EXT-04 — complete meeting history

The group page now offers earlier meeting records through a native button instead of ending at the latest twelve. Pages use descending meeting date, creation time and unique ID, so tied timestamps do not skip or repeat existing records. The continuation is an existing meeting ID scoped to the same group. Each page has at most twelve records; a thirteenth row determines whether another page exists. Removed or foreign cursors fail explicitly and require reopening the group. This is a live history, not a frozen export: new backdated records can appear on subsequent pages.

`GET /api/groups?action=meetings&groupId=…&before=…` decides public access, current membership and private columns in the same SQL statement. Only current members receive reflections. Visitors cannot see attendance counts when the roster is private. Creator identities, invitations and management data are not returned. Malformed records or unconfirmed database reads produce an error rather than invented history. Responses are private/no-store; no migration is needed.

The UI preserves already loaded records after transient errors, retries the same cursor, suppresses duplicate clicks and rejects malformed or repeated pages. Route/account guards prevent delayed responses from updating a replacement view. Confirmed lost access clears loaded history. A keyboard-triggered continuation focuses the first new meeting heading, unless the user has moved focus; the live status announces count, completion or recovery. UK/RU/EN controls retain existing language parity.
