**Статус:** `CLOSED_FOR_DEVELOPMENT_SCOPED / TERMINAL`, 2026-10-31.

## Предмет приймання

У канонічному `app/api/account/route.ts`, авторизований `GET /api/account?action=reading` законно відхиляє збережений JSON із понад 2 000 записів читання. Попередній `PUT?action=reading` перевіряв обсяг лише **вхідного** списку, але об'єднував його з чинним списком без загального ліміту. Коректний за своєю формою спадковий список із 2 000 рядків і одна нова глава спричиняли успішний запис, після чого `GET` повертав 503.

## Завершений функціонал

- Застосовано перевірку ліміту **в тій самій атомарній SQLite/D1 UPSERT**, яка об'єднує читання. Кількість нових записів визначається за канонічними `book` і `chapter`.
- Повторення вже збереженої глави не витрачає місце та не призводить до відмови.
- Переповнення не змінює існуючі приватні дані й не дає хибного підтвердження HTTP 200.
- Чинний контракт невизначеного або нульового D1 write-ack залишається HTTP 503 `reading_save_failed`, а не помилковий HTTP 409; існуючий API не перейменовано.
- Жодного паралельного бекенду, нового API, обхідного зберігання, змін ідентичності чи налаштувань production.
