# SA-EXT-04 — correct meeting notes and attendance

The current group owner can correct the reflection and attendance on any meeting. A current facilitator can correct meetings they authored. Ordinary members, former facilitators and outsiders cannot edit. The paginated history computes `canEdit` in the same SQL statement as visibility; the write independently rechecks current ownership/membership and original authorship inside its UPDATE.

`POST /api/groups?action=meeting-notes` takes exact group/session IDs, `notes` and `expected`. Each object contains only nullable `reflection` (at most 1200 characters) and nullable integer `participantCount` (1–500). A single SQL update checks both original values. Stale data or revoked authority returns 409. An uncertain write returns 503; an authorized GET of the same action provides explicit readback. Text is preserved without truncation. Book, chapter, date, scores, authorship and marathon calculations cannot be changed through this action. No schema migration is required.

Native controls appear beneath an editable meeting. Saving updates the corresponding displayed reflection/attendance after acknowledgement. Errors keep the draft and disable another save until the member explicitly reloads. Reloading a changed draft requires confirmation. Route/account guards suppress stale controls and replies; duplicate requests are prevented and keyboard focus recovers without overriding a user's focus movement. Loading older history does not rebind existing forms or discard edits. The three current interface languages have matching controls; no new language rollout is included.

Tests cover actual migrated SQLite permissions, stale writes, owner/facilitator role races, typed values and corrupted acknowledgements; actual controllers cover drafts, focus, reload recovery and account changes. The disposable two-account Worker/D1 flow verifies an authorized correction, unauthorized and stale refusals, readback and anonymous privacy. This is source functionality, not whole-section or production acceptance. Sites publication remains blocked by `project_not_found`; physical browser/NVDA remains unverified.
