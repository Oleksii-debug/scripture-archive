# SA-EXT-04 — editing existing group settings

Owners can edit the existing group's name, description, community/church, country, city, public/private visibility and member-list visibility. The form lives on the group page and uses native labelled inputs, selects and a disclosure. Publishing a previously private group requires an explicit confirmation that its description, location and aggregate results become visible. Individual name-consent flags remain authoritative; changing the roster to names does not reveal members who withheld consent. Private meeting reflections remain member-only.

The existing groups API accepts `action=settings` with complete `settings` and `expected` snapshots of the seven editable fields. The same SQL UPDATE checks the authoritative owner, owner membership and exact expected previous values. A stale tab or former owner receives 409 instead of overwriting a newer value. Values retain their complete text; malformed fields, unknown settings, unsupported visibility values and overlong text are rejected before mutation. The write must return a successful D1 receipt with exactly one changed row before the API reports success. No migration is required.

The form preserves the draft on conflict or uncertain save. Reload is explicit and warns before discarding it. A successful save reloads server state and returns focus to the settings disclosure. Existing route/session guards prevent retained controls and delayed responses from writing, navigating or announcing after an account change. The settings editor does not alter the group's invitation, members, records, edition, pace or marathon cohort.

Verification: actual TypeScript route with the full migrated SQLite schema; concurrent edits, transferred ownership between read and write, refused outsiders, malformed inputs, exact maximum-length text, failed/absent D1 receipts, public/private readback and consent; controller tests for draft preservation, account/route changes, duplicate clicks, confirmation and focus; the local Worker two-account flow also edits metadata and visibility, rejects stale/unauthorized edits and verifies private access afterward.
